# 基于 Linux 的烟雾报警系统

运行在 ARM Linux 开发板上的烟雾浓度监测与报警系统：通过串口读取 MQ2 烟雾传感器数据，在 800×480 触摸屏上实时显示浓度，支持触摸调节报警阈值，超限自动报警。

## 功能

- 触摸解锁进入主界面，带滑动过渡动画
- 实时显示 MQ2 烟雾浓度与当前报警阈值
- 触摸屏 `+` / `-` 按钮调整阈值
- 浓度超过阈值时切换为报警画面，正常时显示正常画面
- 1 秒周期采样，界面持续刷新

## 硬件环境

| 部件 | 说明 |
|------|------|
| 主控 | ARM Linux 开发板 |
| 显示 | 800×480 LCD，`/dev/fb0`，32 位色 |
| 触摸 | 触摸屏，`/dev/input/event0`（input 子系统） |
| 传感器 | MQ2 烟雾传感器模块，UART 9600 8N1 |
| 串口 | `/dev/ttySAC1` |

## 系统架构

```
┌──────────────┐   UART 9600   ┌──────────────────────┐   mmap    ┌──────────────┐
│ MQ2 烟雾传感器│ ────────────→ │  Linux 应用程序 yw.c  │ ────────→ │  /dev/fb0     │
└──────────────┘               │                      │           │  800×480 LCD  │
┌──────────────┐  input_event  │  采集线程 / 主循环    │           └──────────────┘
│   触摸屏      │ ────────────→ │  阈值调节 / 解锁      │
└──────────────┘               └──────────────────────┘
```

## 软件设计

### 1. 串口采集

使用 `termios` 将 `/dev/ttySAC1` 配置为 9600、8 数据位、无校验、1 停止位，发送固定查询帧：

```
FF 01 86 00 00 00 00 00 79
```

再以 `0xFF` 为帧头接收 9 字节响应，浓度值由第 3、4 字节拼接：

```c
value = recvbuf[2] << 8 | recvbuf[3];
```

### 2. 帧缓冲显示

- `open("/dev/fb0")` + `mmap` 映射 800×480×4 字节显存，直接写像素
- 解析 BMP 文件头（偏移 18、22 取宽高，偏移 54 开始取像素），逐点写入并处理上下翻转
- 数字显示使用 8×10 点阵字模，缩放到 40×40，固定显示 3 位（带前导零），背景 150×50
- 滑动动画通过分步偏移绘制 BMP 实现

### 3. 触摸输入

读取 `/dev/input/event0` 的 `struct input_event`：

- `EV_ABS` + `ABS_X / ABS_Y` 记录坐标
- `EV_KEY` + `BTN_TOUCH` 为 0 表示抬手，结束一次触摸

触摸处理放在独立线程中，主线程只负责采集与刷新，互不阻塞。

### 4. 交互逻辑

- 解锁：在指定坐标区域触摸后播放滑动动画，进入主界面
- 阈值调节：主界面底部左右两个区域分别对应 `+` / `-`，默认阈值 80
- 报警判断：`value > yz` 显示报警画面，否则显示正常画面

## 编译与运行

```bash
arm-linux-gcc yw.c -o yw -lpthread
```

运行前：

1. 把 `图片素材/` 下的 BMP 复制到可执行文件同目录（程序使用相对路径读取）
2. 确保当前用户有 `/dev/fb0`、`/dev/input/event0`、`/dev/ttySAC1` 的读写权限（通常需要 root）
3. 连接 MQ2 模块到对应串口后运行 `./yw`

## 已知问题

- 程序引用了 `jb.bmp`（报警）和 `cb.bmp`（正常），素材目录中目前只有 `bj.bmp`、`kb.bmp`，需补齐或改名
- BMP 像素缓冲使用变长数组分配在栈上，图片较大时可能栈溢出，建议改为 `malloc`
- 串口读取没有超时处理，传感器无响应时会一直阻塞
